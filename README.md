# Кейтеринг «Сибирский стол» — Вариант 15 (ПР23-КТР)

Программный комплекс для **кейтеринговой компании и выездного ресторанного обслуживания** (учебная практика УП.01.01, модуль ПМ.01).
Расчёт калькуляции выездных банкетов, аренда сервировочного оборудования и учёт рабочего времени персонала.

> ТЗ: «Индивидуальная карточка задания № 15, Шифр: КТР | Группа: ПР-23 | ПМ.01».
> Требования: `Требования к проекту.pdf` (1.1–1.5).

## Состав решения (.NET 10, MVVM)

```
Catering.sln
├── src/Catering.Core     — библиотека классов: POCO-модели, EF Core (Pomelo MySql) AppDbContext,
│                            сервисы бизнес-логики, SHA256-контрольные суммы, валидаторы (Regex)
├── src/Catering.Desktop  — Avalonia UI 11: XAML-Views, ViewModels (CommunityToolkit.Mvvm),
│                            стили, конвертеры, Assets, DI-регистрация зависимостей
└── src/Catering.Tests    — xUnit: 15 модульных тестов бизнес-логики и FSM
```

Архитектура строго по PDF 1.1–1.5: паттерн **MVVM + CommunityToolkit.Mvvm**, расчётная логика вынесена в
независимый `CateringCalculationService` (без зависимостей от UI), сохранение документов — **транзакционное**
(`BeginTransactionAsync`), чтение Master-Detail — через `Include(x => x.MenuItems)`.

## Роли пользователей

| Роль (roles)            | Права |
|-------------------------|-------|
| Администратор (шеф-менеджер кейтеринга) | технологические карты банкетного меню, тарифы на посуду и мебель, все операции |
| Менеджер (банкетный координатор)       | приём заказов, составление сметы мероприятия, назначение выездных бригад |

## База данных (MySQL/MariaDB, 7 таблиц, 3НФ)

Таблицы: `roles`, `users`, `event_types`, `banquet_dishes`, `catering_clients`,
`catering_contracts` (заголовок) + `contract_menu_items` (спецификация). DDL и демо-данные — в **`db/schema.sql`**
(первичные ключи `id INT AUTO_INCREMENT`, явные `FOREIGN KEY … ON DELETE RESTRICT/CASCADE`, чек-констрейнты;
в каждой таблице 5–10+ записей, итоги сходятся по формуле калькуляции).

### Шаг 1. Создание БД через phpMyAdmin
1. Запустите MySQL/MariaDB + Apache (XAMPP / OpenServer / Denwer).
2. Откройте **http://localhost/phpmyadmin/** → вкладка **Импорт** → выберите `db/schema.sql` → **Вперёд**.
   Скрипт сам создаст базу `catering_db` и все таблицы с данными.
3. (Либо консолью: `mysql -u root < db/schema.sql`)

### Шаг 2. Строка подключения
По умолчанию (`src/Catering.Desktop/Services/ConnectionOptions.cs`, XAMPP: root без пароля):

```
Server=localhost;Port=3306;Database=catering_db;User Id=root;Password=;CharSet=utf8mb4;
```

Переопределение без перекомпиляции — переменная окружения `CATERING_CONNECTION_STRING`.

### Шаг 3. Запуск
```bash
dotnet restore
dotnet run --project src/Catering.Desktop
```

### Шаг 4. Модульные тесты
```bash
dotnet test
```

`InvalidOperationException` при недопустимом переходе (Тест 4), отмена < 10 символов, маска номера, SHA256-вектор и т.д.

## Экраны

1. **LoginWindow** — авторизация; поле пароля скрыто маской `PasswordChar="*"` с кнопкой показа;
   **3 неверные попытки → блокировка на 10 секунд** с визуальным обратным отсчётом (`DispatcherTimer`).
2. **MainWindow** — ФИО и роль сотрудника, кнопка «Сменить учётную запись»; таблица договоров (DataGrid):
   интерактивный поиск, фильтр по статусам, сортировка по столбцам (выбор столбца + направление ⇅,
   двойной клик по строке открывает документ), **цветовая индикация критических состояний**
   (просроченные выезды подсвечены, счётчик в сайдбаре и в строке), часы и **обратный отсчёт T− до
   ближайшего выезда** (`DispatcherTimer`).
3. **Master-Detail (ContractEditorWindow)** — шапка договора + встроенная таблица спецификации
   (редактируемые ячейки: порции/аренда). Добавление, редактирование и удаление позиций
   **на лету пересчитывают итоги** через привязки данных:
   `line_cost = servings_count × cost_per_person + equipment_rent_fee`;
   `total = (Σ line_cost − VIP 10%) × service_multiplier + 500 ₽ × guests_count`.
4. **Модальные диалоги** — подтверждение удаления; причина отмены (обязательно, ≥ 10 символов);
   быстрый диалог создания клиента с **Regex-валидацией телефона** `+7 (XXX) XXX-XX-XX`;
   номер документа проверяется маской `ПР23-КТР-{Год}-{Номер:D5}`.

## Бизнес-логика (вариант 15)

- **Калькуляция сметы** (`CateringCalculationService`):
  `LineCost = servings_count · cost_per_person + equipment_rent_fee`;
  к сумме блюд применяется **наценка за сложность площадки** `service_multiplier`
  (напр. `1.25` для открытых площадок без стационарной кухни), **обслуживание персоналом +500 ₽/персону**,
  VIP-клиентам — **льгота 10%** на сумму блюд.
- **Конечный автомат (FSM)**: `Предварительный расчет → Смета утверждена → Закупка сырья →
  Банкет проведен`, из любого незакрытого статуса — `Отмена клиентом`.
  - «Смета утверждена» **блокируется**, если `guests_count < min_guests` выбранного типа мероприятия;
  - пустой договор (0 позиций) нельзя переводить в утверждение/оплату;
  - закрытый документ (`Банкет проведен` / `Отмена клиентом`) редактировать и переводить нельзя;
  - отмена требует причину (`cancel_reason`) **не короче 10 символов**;
  - недопустимый переход → `InvalidOperationException`.
- **Маска номера документа**: `ПР23-КТР-{Год}-{Номер:D5}`, напр. `ПР23-КТР-2026-00042`
  (генерация автоматическая, год — текущий).
- **Контроль целостности и SHA256**: при экспорте сметы (`.txt` / `.csv` / `.html`) сервис формирует
  каноническую строку реквизитов
  `[Номер]|[Дата yyyy-MM-dd HH:mm:ss]|[Контрагент]|[Сумма 0.00]|[КоличествоПозиций]`
  и печатает подпись **SHA256** нижней строкой документа.
- **Таймер обратного отсчёта** (`Avalonia.Threading.DispatcherTimer`, интервал 1 с):
  напоминание о выезде шеф-повара и подаче первых блюд, автоподсветка просроченных обязательств.
- **Master-Detail**: заголовок + спецификация, навигационные свойства EF Core
  (`Include(x => x.MenuItems).ThenInclude(i => i.BanquetDish)`), сохранение в транзакции
  (`using var transaction = await context.Database.BeginTransactionAsync()`).

## Замечания по сборке

Решение написано под **.NET 10 SDK** (`net10.0`, C# 14) и пакеты: `Avalonia 11.3.0`,
`CommunityToolkit.Mvvm 8.4.0`, `Microsoft.EntityFrameworkCore 9.0.0`,
`Pomelo.EntityFrameworkCore.MySql 9.0.0`, `xunit 2.9.2` (EF Core 9 собран под net8.0 и полностью
совместим с net10.0; Pomelo для EF Core 10 на NuGet на момент сборки отсутствовал — ближайший 9.0.0).
В корне лежит `global.json` (`10.0.100`, rollForward `latestFeature`) — подхватится SDK 10.0.112.
Сборка локально в среде подготовки не выполнялась (официальные каналы .NET/NuGet оттуда недоступны);
код проверялся статическим анализом (синтаксис, баланс скобок, XML/XAML, ссылки на ресурсы и биндинги).

Порядок проверки на машине с интернетом:

```bash
dotnet restore && dotnet build && dotnet test
```

Если `restore` сообщит, что какой-то патч не найден на вашем NuGet-канале, выполните
`dotnet add <проекта> package <имя>` без `--version` — будет выбрана максимальная доступная версия.
Пара EF Core ↔ Pomelo обязана совпадать по мажорной версии (EFC9 ↔ Pomelo 9, EFC10 ↔ Pomelo 10, когда выйдет).
Шаг `dotnet add package` сам поднимет остальные зависимости. .NET 8 рантайм для запуска **не требуется** —
всё перецелено на net10.0.
